## 三、可借鉴之处

### 3.1 "MVP"这个词值得学

MVP = **最小可行产品**：不追求功能完备，只做一个能跑通、能演示、
能证明核心价值的最小版本。

**对我们的启示**：我们的结题演示不必做成"业务系统"，
但应该有一个**能点开、能输入、能出结果**的最小原型，例如：

```
输入：某年某月某日（作为发布时刻）+ 提前期（1/2/3/4 周）
输出：预测的 H 值 + 折算出的区域 Tmax 距平 + 高温风险等级（蓝/黄/红）
      + 该预测的主要贡献因子（SHAP 前 3 项）
```

这个原型完全建立在规划书已有的模块之上，额外工作量很小，
但对答辩效果的提升很大。

### 3.2 跨学科团队也能做气象类作品

团队来自**管理学院**，并非大气科学专业，却拿下"人工智能+"专项赛全国二等奖。
说明：

- 挑战杯"人工智能+"专项赛**不要求参赛者必须是该领域专业出身**；
- **场景理解 + 产品化能力**本身就是竞争力。

**对我们的启示**：我们的作品叙事不应过度堆砌气象术语，
而应让非气象背景的评审也能听懂"这解决了什么问题、效果如何"。
这正是规划书 [`09_概念词典.md`](../../notebooks/项目规划书/09_概念词典.md)
和拟议中的"通俗版原理说明一页纸"的用途。

### 3.3 智能体（Agent）框架是新热点

ReAct 框架属于大模型智能体范式的代表。赛事对"AI 新范式 + 传统行业"
的组合是鼓励的。

**对我们的启示**：我们第一阶段**不应该**上大模型/智能体，
但可以在**成果展示层**（如预警原型的交互界面）适度引入自然语言交互，
作为"包装层"而非"方法层"。**方法与包装要分开**，避免被质疑"技术堆砌"。

### 3.4 8 人本科生团队

团队规模较大且全为本科生，说明本科生主导的作品同样可以拿国奖，
关键在于**选题贴近需求 + 呈现清晰**。

## 四、不能照搬的地方

| 他们的做法 | 我们的差异 |
| --- | --- |
| 以产品/小程序为核心卖点 | 我们的核心必须是**预测方法的技巧与物理解释**，产品只是展示层 |
| 大模型智能体框架 | 我们第一阶段用线性模型/树模型，样本量不支持大模型 |
| 农业场景的定性建议 | 我们要求定量技巧评估（RMSE/R²/HSS）与显著性检验 |
