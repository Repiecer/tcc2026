## 二、项目做了什么（官方简介要点）

> 项目聚焦气象雷达数据中**气象回波与非气象回波的智能区分**，
> 旨在为气象防灾减灾、天气预警及航空气象保障提供精准、高效的技术支持。
> 团队创新性地提出了**自动标签生成技术**，并设计了
> **结合特征值和模糊逻辑算法的深度学习融合网络**，成功实现了
> **高准确率、高实时性、强可解释性且具备业务化应用能力**的 "EchoPrint" 网络。
>
> ——南京大学大气科学学院官网新闻稿

技术要点：

1. **自动标签生成技术**——解决人工标注样本不足的问题（一种弱监督/自动化数据构造思路）；
2. **深度学习融合网络 + 特征值 + 模糊逻辑**——不是纯端到端黑箱，而是把
   传统特征与模糊规则嵌入网络设计中；
3. **四个并列的成果形容词**：高准确率 / 高实时性 / **强可解释性** / 业务化应用能力。

---

## 三、这个案例最值得我们学的一点：**把"可解释性"当卖点写**

在很多机器学习项目里，"可解释性差"是被动承认的缺陷。
这个作品把它反过来，作为**与准确率、实时性并列的核心优势**写在简介里。

对照我们的规划书：

| 他们的表述 | 我们的对应 |
| --- | --- |
| 强可解释性 | **SHAP + Permutation Importance + 分组消融三重证据** |
| 结合特征值与模糊逻辑 | 用已知物理假设约束因子选择（陆面干湿链、环流链） |
| 业务化应用能力 | 极端高温分级预警原型 + 独立年份历史回报检验 |
| 自动标签生成 | 训练期分位阈值自动生成极端/非极端标签 |

**建议在答辩 PPT 的方法页直接写一句：**

> "本工作不是黑箱模型：每一个关键预测因子都通过了
> SHAP 贡献、置换重要性与分组消融三重检验，
> 并通过合成分析与环流诊断验证其物理合理性。"

## 四、其他可借鉴之处

1. **依托重点实验室**——把"中尺度灾害性天气教育部重点实验室"写进简介，
   增强作品的可信度与研究基础。我们可依托本校的实验室/课题组平台，
   在作品简介中体现。
2. **明确的行业服务对象**——"气象防灾减灾、天气预警、航空气象保障"三个场景并列，
   让评审迅速理解价值。我们的对应场景：**电力调度、农业高温热害、公众健康防护**。
3. **7 名本研混合团队**——本研搭配是挑战杯的常见结构：
   本科生做工程实现，研究生做方法把关。可作为我们组队的参考。
4. **同一个作品多次获不同赛事奖项**——"指纹"解构与案例 02 中的 EchoPrint
   是同一套技术的不同命名/不同赛道版本（分别在"揭榜挂帅"与校内展示渠道出现），
   说明**同一技术成果可以多赛道、多渠道复用包装**。

## 五、不能照搬的地方

| 他们的做法 | 我们的差异 |
| --- | --- |
| 图像/回波识别（深度学习主场） | 我们是表格型气象数据的回归/分类（树模型与线性模型更合适） |
| 有明确标注体系（气象/非气象） | 我们的"极端/非极端"标签需要自己用分位数定义，且**阈值必须只用训练期确定** |
| 准确的"标准答案"可对照 | 我们的"真值"是再分析资料，本身含模式误差，需要在报告中说明 |
