## ⭐ 四个提前期的因子增量：一条非常干净的规律

把每个因子"叠在持续性基线上"的增量 R² 按提前期排开（train + val）：

| 因子 | lead 1 周 | lead 2 周 | lead 3 周 | lead 4 周 | 类型 |
|---|---|---|---|---|---|
| 持续性基线 R² | 0.1118 | 0.0077 | 0.0053 | 0.0000 | — |
| `tp_yrb_sum7` 降水 | **+0.0490** ✅ | +0.0050 | 0 | 0 | 快 |
| `olr_yrb_pre7` 辐射 | **+0.0456** ✅ | ~0 | ~0 | ~0 | 快 |
| `u850_shear_ns_pre7` 反气旋 | **+0.0413** ✅ | +0.0096 | 0 | +0.0020 | 快 |
| **`swv3_yrb_pre7` 深层土壤** | +0.0042 | **+0.0225** ✅ | +0.0131 | **+0.0146** ✅ | **慢** |
| `swv1_yrb_pre7` 表层土壤 | +0.0052 | +0.0097 | +0.0097 | +0.0057 | 慢 |
| **`sst_wpwp_pre7` 西太暖池** | +0.0136 ✅ | +0.0180 ✅ | **+0.0219** ✅ | **+0.0455** ✅ | **慢** |
| `mslp_*` 气压 | +0.016 ~ +0.022 ✅ | — | — | — | 快 |
| `t850_*` 低层气温 | +0.002 ~ +0.022 | — | — | — | 快 |

> ### ⭐ 核心结论
>
> **短期（提前 1 周）靠"天气快变量"（降水、环流、辐射）；
> 延伸期（提前 2-4 周）只能靠"慢变量"（深层土壤 + 海洋暖池）。**
>
> - 快变量（TP / OLR / U850 切变）在提前 1 周增量最大，但**提前 2 周就归零**；
> - **两个慢变量**覆盖延伸期：`swv3`（土壤，提前 2/4 周显著）与
>   `sst_wpwp`（暖池，**四个提前期全部显著且增量随提前期递增**，4 周达 +0.0455）；
> - 物理原因：**大气热惯性只有几天，土壤记忆以周计、海洋记忆以月计**。
>
> **这解释了为什么单纯堆环流因子做不出延伸期技巧**，
> 也说明建模时必须**按提前期分别选因子**，而不是四个提前期共用一套因子。


## P0 冻结项（一旦改动，全部下游结果作废）

| # | 决定 | 取值 | 理由 |
|---|---|---|---|
| 1 | **目标定义** | **T2：周平均 H**（窗口固定 7 天）| 规划书 04 推荐的主目标；比日尺度噪声小 |
| 2 | **提前期** | k = 1, 2, 3, 4 周，四张独立表 | 规划书 04 第 3 节 |
| 3 | **发布间隔** | **7 天**（不重叠周）| 见下方"为什么不用每天发布" |
| 4 | **因子窗口** | 固定 7 天，右端 = `issue_date` | 防泄漏铁律 L2 |
| 5 | **样本年份** | 1982-2025（1981 不用）| SST 从 1982 起，为了让 42 列全无缺测 |
| 6 | **数据划分** | 训练 1982-2015 / 验证 2016-2020 / 测试 2021-2025 | 铁律 L1（按年块，禁止随机打乱）|

## 列定义

### 元数据列

| 列名 | 含义 |
|---|---|
| `issue_date` | **发布时刻 t0**（防泄漏校验的关键列，只能用这一天及以前的信息）|
| `feature_start` / `feature_end` | 因子聚合窗口 = `[t0-6, t0]`，**右端严格 ≤ t0** |
| `target_start` / `target_end` | 目标窗口 = `[t0+7(k−1)+1, t0+7k]`，长度恒为 7 天 |
| `lead_week` | 提前期标签（1/2/3/4）|
| `year` | 发布年，用于按年划分 |
| `issue_block` | 季节内第几周（0-15），供**分块交叉验证**使用 |
| `split` | `train` / `val` / `test` |

### 目标列

| 列名 | 含义 | 单位 |
|---|---|---|
| `Y` | 目标窗口内 **H 的平均值** | 无量纲（z 分数）|
| `Y_raw` | 目标窗口内**区域平均 Tmax** 的平均值 | degC |

### 因子列（31 列）

命名规则：`{变量}_{指数}_{聚合}`，聚合后缀有两种：

- **`_pre7`** — 窗口内 **7 天平均**（状态量：温度、风、位势高度、土壤湿度、SST）
- **`_sum7`** — 窗口内 **7 天累计**（只有 `tp_yrb_sum7`，降水是累积量）

| 变量 | 指数 | 列名示例 |
|---|---|---|
| 高温指数（持续性基线）| — | `H_pre7` |
| 表层土壤湿度（0-7 cm）| yrb | `swvl1_yrb_pre7` |
| **第 2 层土壤湿度（7-28 cm）** | yrb | `swv2_yrb_pre7` |
| **第 3 层土壤湿度（28-100 cm）** | yrb | `swv3_yrb_pre7` |
| 降水 | yrb | `tp_yrb_sum7` |
| 2 米露点 | yrb | `d2m_yrb_pre7` |
| **向外长波辐射（替代 ssrd）** | yrb | `olr_yrb_pre7` |
| 海平面气压 | yrb, north, south | `mslp_yrb_pre7` |
| 500 hPa 位势高度 | wpsh, yrb, scs, midlat | `z500_yrb_pre7` |
| 200 hPa 位势高度 | sah, ea, yrb, midlat | `z200_yrb_pre7` |
| 海表温度 | nino34, wpwp, iod_w, iod_e, scs | `sst_nino34_pre7` |
| 850 hPa 气温 | yrb, north, south, grad_ns | `t850_yrb_pre7` |
| 850 hPa 纬向风 | yrb, north, south, **shear_ns** | `u850_shear_ns_pre7` |
| 850 hPa 经向风 | yrb, north, south | `v850_yrb_pre7` |

> ⚠️ **所有因子列都是标准化指数（z 分数），不是物理量。**
> 需要物理量时查 `data/proc/{var}_anomaly.nc`（距平）或原始 nc。
> `H_pre7` 是**持续性基线**：它本身已扣除季节循环，代表"发布前一周有多热"。
>
> 为什么用 z 分数而不是原始单位：不同变量的量纲（K、hPa、m/s、m³/m³、gpm）
> 无法直接比较系数大小；标准化后 31 个因子的权重才可比。

## 防泄漏校验

运行 `MPLCONFIGDIR=logs .venv/bin/python scripts/check_leakage.py`，逐条断言：

| 检查 | 内容 |
|---|---|
| **L1** | train / val / test 年份集合互不相交，且各自连续覆盖 |
| **L2** | `feature_end == issue_date`；因子窗口长度恒为 7 |
| **L2** | `target_start > issue_date`；**因子窗口与目标窗口不重叠** |
| **附加** | 目标窗口长度恒为 7；`target_start = issue_date + 7(k−1)+1` |
| **附加** | 42 列无任何缺测；`(issue_date, lead_week)` 无重复 |
| **独立重算** | 用纯 pandas 重算 `Y` 与一个因子，最大差 < 1e-15 |
| **端到端** | 从**原始 nc** 走完整链路（提取 → 面积加权 → 减 clim → 除 sigma → 窗口平均）重算一行，差 5.6e-17 |

## 为什么不用"每天发布"

如果发布间隔改成 1 天，样本数会涨到约 4000，但**相邻样本的目标窗口
大量重叠** —— 名义样本量远大于有效样本量，相关系数和技巧评分的置信区间
会被严重低估（规划书 04 第 4.3 节明确警告过这一点）。

现在的 7 天间隔保证**同一张表内任意两个样本的目标窗口互不重叠**，
可以直接用常规显著性检验。

若确实需要"每天发布"的操作版本：

```bash
MPLCONFIGDIR=logs .venv/bin/python scripts/build_dataset.py --step 1
```

此时**必须**改用按年分块 bootstrap 做显著性检验。

## 已知事项

- 训练集只有 442-544 个样本、31 个因子的情况下，**过拟合风险很高**。
  线性模型（L2）应优先使用分组消融（A-E 组）而不是一次性塞入 31 个因子。
- 样本年份从 1982 起（少了 1981），原因是 SST 数据从 1982 年才开始。
  损失 1 年训练数据（约 3%）可以接受，换来 42 列零缺测。
- `Y_raw` 只用于物理解释与反向换算，**不要**用它当训练目标
  （未去除季节循环，会让模型退化成"看日期猜气温"）。
- 样本表依赖 `data/proc/*_indices.nc`。**任何一次标准化脚本重跑之后，
  都必须重新运行 `build_dataset.py`**，否则样本表与因子源不一致。
