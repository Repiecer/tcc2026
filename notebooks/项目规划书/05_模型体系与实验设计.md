## 一、为什么必须建"基线"：分层模型体系

原方案明确指出：**不建议一上来只做一个 XGBoost**。原因是答辩时必须能回答：

> "机器学习到底比简单方法提高了多少？"

如果没有基线，一个 XGBoost 报出 R = 0.5，评审无法判断这是"很厉害"
还是"用持续性预测就能拿到 0.45"。因此设计五层模型：

| 层级 | 模型 | 角色 | 预期技巧 | 回答的问题 |
| --- | --- | --- | --- | --- |
| **L0** | 气候态基线 | 最朴素参照 | 最低（作为技巧评分的分母） | "如果只会说'和常年一样'，能得多少分？" |
| **L1** | 持续性基线 | 利用高温自相关 | 较高（尤其提前 1 周） | "如果只会说'上周热，这周也热'，能得多少分？" |
| **L2** | Linear Regression / Ridge | 线性统计基线 | 中等 | "线性关系能解释多少？" |
| **L3** | Random Forest Regression | 非线性集成 | 中—高 | "非线性带来了多少增量？" |
| **L4** | XGBoost Regression（核心） | 梯度提升 | 目标最高 | "当前方法能做到什么水平？" |

### 1.1 L0 气候态基线（Climatology）

因为目标 H 已经减去了气候态，所以：

```
Ŷ = 0
```

**这是最关键的分母**：任何模型的技巧评分（skill score）都以它为参照。
若模型不能显著超过气候态，说明它没有捕捉到任何有用信息。

### 1.2 L1 持续性基线（Persistence）

```
Ŷ(t) = H(t − 7k)      # 用 k 周前的实测 H 作为预测
```

更严谨的变体：用发布时刻前 7 天的平均 H，或用 AR(1) 自回归外推。
持续性基线通常在第 1 周很强、随提前期迅速衰减——
**它的衰减速率本身就是"延伸期可预测性"的直观度量**。

### 1.3 L2 线性模型

- **Linear Regression（OLS）**：系数可直接解释为"该因子变化 1 个标准差时，
  H 变化多少"，是最透明的模型；
- **Ridge（L2 正则）**：气象因子之间存在强多重共线性（如 TP 与 SWVL1、
  T2m 与 SSRD），OLS 系数会极不稳定；Ridge 通过惩罚系数幅度稳定估计；
- **Lasso（L1 正则）**：可自动把无用因子系数压缩为 0，起到变量筛选作用，
  可作为因子筛选的辅助证据；
- **必备前置步骤**：特征标准化（z-score），否则正则化惩罚对不同量级的变量不公平。

### 1.4 L3 随机森林（Random Forest Regression）

- **原理**：对训练集做有放回重采样（bootstrap），训练多棵决策树，
  每棵树在分裂时只随机考虑部分特征；最终取所有树预测的平均。
- **优点**：能刻画非线性与变量交互；对超参数不敏感；不易过拟合；自带重要性度量。
- **缺点**：**不能外推**——树模型预测值永远落在训练样本 Y 的取值范围内，
  因此对"超出历史极值的高温"会系统性低估；解释性弱于线性模型。

### 1.5 L4 XGBoost（eXtreme Gradient Boosting）

- **原理**：串行地一棵一棵加树，每棵新树拟合前面所有树的**残差**
  （严格说是损失函数的负梯度），并用正则项控制模型复杂度。
- **优点**：在表格型数据上通常是最强的方法；训练快；内置缺失值处理与正则化。
- **缺点**：超参数多（学习率、树深、树数、子采样比例、列采样比例、
  正则系数等），调参不当极易过拟合；同样不能外推。
- **同族备选**：项目中已安装 `lightgbm` 与 `catboost`，效率与表现往往接近 XGBoost，
  可作为**鲁棒性检验**（"换一个提升算法，结论是否依然成立？"），
  但**不建议在第一阶段同时调三个**，避免算力与注意力分散。

### 1.6 关于深度学习的取舍

原方案明确：**第一阶段不建议直接使用 LSTM、Transformer 等复杂深度学习模型。**
理由：

1. 样本量有限（周平均后约 780 个样本），深度模型极易过拟合；
2. 可解释性差，难以支撑"关键因子物理机制"这一核心目标；
3. 层次清晰、容易比较的模型体系更符合"从简单到复杂"的科学论证逻辑。

**拓展条件**：只有当 L2—L4 的完整流程（含防泄漏、独立检验、消融、SHAP）
全部跑通并有稳定结果后，才考虑把序列模型作为对比实验。

## 二、数据集划分方案

### 2.1 主划分（时间块划分，禁止随机打乱）

| 数据集 | 年份 | 用途 | 使用规则 |
| --- | --- | --- | --- |
| **训练集** | 1981—2015（35 年） | 拟合模型参数、拟合气候态与标准化参数 | 可反复使用 |
| **验证集** | 2016—2020（5 年） | 调超参数、选因子、做消融实验 | 可反复使用，但每次实验须记录 |
| **独立测试集** | 2021—2025（5 年） | 最终泛化能力检验 | **只用一次**，模型冻结后使用 |

> 若数据年份范围或研究区调整，需同步更新此表并在
> [`02_技术路线与总体流程.md`](02_技术路线与总体流程.md) 的变更记录中登记。

### 2.2 滚动验证（Rolling / Walk-forward Validation）

单一验证集只有 5 年，样本少、结论易受个别年份影响。
因此增加**滚动验证**：用不断向前推进的时间窗口做多次"训练—验证"，

```
第 1 折：训练 1981—2005  → 验证 2006—2010
第 2 折：训练 1986—2010  → 验证 2011—2015
第 3 折：训练 1991—2015  → 验证 2016—2020
...（可继续外推）
```

两种窗口形式：

| 形式 | 说明 | 适用 |
| --- | --- | --- |
| **扩展窗口**（expanding） | 训练集起点固定，终点逐折后移 | 样本量有限时首选，充分利用历史信息 |
| **滑动窗口**（sliding） | 训练集长度固定，整体后移 | 检验"只用近 N 年数据"是否更好 |

**滚动验证的作用**：
1. 给出技巧的**年际不确定性范围**（不是单个数字，而是分布）；
2. 检验模型的**时间稳定性**——若某几折技巧突然崩塌，说明模型依赖了不稳定的偶然关系；
3. 为显著性检验提供更多独立样本。

⚠️ 注意：气象时间序列自相关强，滚动验证的各折结果**并不完全独立**，
解读时须保守。

### 2.3 交叉验证的正确用法

- ✅ 时间序列交叉验证（`TimeSeriesSplit` 或自实现的分块 CV）；
- ❌ 随机 K 折（`KFold(shuffle=True)`）——会让未来样本进入训练集，属于 L1 违规。

## 三、超参数调优协议

| 环节 | 规定 |
| --- | --- |
| 搜索方法 | 先随机搜索（Random Search）粗筛，再在最优区域做网格细化 |
| 搜索空间（XGBoost 示例） | `n_estimators` 200—2000、`learning_rate` 0.01—0.1、`max_depth` 2—6、`subsample` 0.6—1.0、`colsample_bytree` 0.6—1.0、`reg_lambda` 0—10 |
| 搜索空间（RF 示例） | `n_estimators` 300—1000、`max_depth` 3—15 或 None、`min_samples_leaf` 1—10、`max_features` 0.3—1.0 |
| 选择准则 | 以验证集 **RMSE** 为主，同时参考 R² 与过拟合间隙（训练—验证差距） |
| **树深要浅** | 延伸期信号弱、样本少，`max_depth` 应偏小（如 2—4），宁可欠拟合也不要过拟合 |
| 早停 | XGBoost 可用验证集早停，但早停用的验证集不能同时用于最终评估（需再切一层或接受轻微乐观） |
| 记录 | 每次试验的超参数、随机种子、验证指标写入实验日志（见第五节） |
| **禁止** | 用测试集（2021—2025）参与任何超参数选择 |

## 四、分组消融实验：识别"哪一类变量真正有用"

### 4.1 设计思想

单变量重要性（如 SHAP 排名）在高相关气象变量之间会**互相分摊贡献**，
导致排名失真。**分组消融**用"加一组变量，技巧提升多少"来回答更可靠的问题。

### 4.2 实验分组（对应 `plans.ipynb` 的 A—E）

| 组别 | 输入变量集合 | 累积内容 | 考察问题 |
| --- | --- | --- | --- |
| **A** | 前期温度类（前期 T2m / 高温指数） | 基准组 | 高温自身的持续性贡献多少？ |
| **B** | A + 土壤湿度与降水（SWVL1、TP） | +陆面干湿 | 陆面记忆带来多少增量？ |
| **C** | B + 辐射与潜热（SSRD、AVG_SLHTF） | +地表能量 | 能量收支因子是否进一步提高技巧？ |
| **D** | C + 环流（Z500、850 hPa 风场、MSLP） | +大气环流 | 环流前兆的增量贡献？ |
| **E** | D + SST | +海温 | 海气相互作用是否还有额外信息？ |

### 4.3 实验纪律

1. **只改输入变量集合**，模型、超参数、数据划分、随机种子完全一致；
2. 每个提前期（1/2/3/4 周）**分别**做 A—E，得到 5 × 4 = 20 组结果；
3. 结果表形式：

| 提前期 | 组别 | 变量数 | RMSE | MAE | R | R² | 相对 A 组的 RMSE 降幅 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 周 | A | … | 待计算 | 待计算 | 待计算 | 待计算 | — |
| 1 周 | B | … | | | | | |
| … | … | … | | | | | |

4. **判读逻辑**：若加入某类变量后技巧无提升甚至下降，说明该类变量
   在控制其他变量后没有独立信息——**这本身是有价值的结论**，
   不要因为"不符合预期"就隐藏。

### 4.4 消融实验与最终因子集合的关系

消融结果 + SHAP + 机制诊断三者结合，确定最终因子集合：

```
A—E 消融  ──→ 哪些变量类别有增量技巧
SHAP 贡献  ──→ 类别内部哪些具体变量贡献大
机制诊断   ──→ 这些变量是否具有可信的物理解释
        ↓
   最终因子集合（写入冻结配置）
```

## 五、模型冻结（Freeze）与独立检验

### 5.1 冻结的含义

在 P4 阶段终点，把以下内容全部**写死**并生成配置哈希：

- 研究区范围与研究时段
- 目标定义（T1 日 H / T2 周平均 H）
- 气候态与标准化参数的估计方式与数值
- 最终因子清单及其聚合窗口
- 模型类型与全部超参数
- 随机种子

产物：`configs/frozen_v1.yaml`，并记录其 SHA256 哈希。

### 5.2 独立检验的执行纪律

```
冻结 → 加载 2021—2025 数据 → 一次性预测 → 计算所有指标 → 出报告
```

- **只跑一次**。不得根据测试结果调整任何设置。
- 测试结果不好也要如实记录。原方案原话：
  "测试结果不好，也不能回来根据 2021—2025 重新挑因子，否则测试集就失去意义。"
- 若确实发现了实现层面的 bug（而非方法问题），可以修复后重跑，
  但**必须在报告中披露**，并同时保留修复前后的结果。

## 六、实验可复现性规范

| 项目 | 规范 |
| --- | --- |
| 环境 | 用 `uv`（仓库已有 `pyproject.toml` 与 `uv.lock`）锁定依赖版本 |

## 七、常见陷阱清单

| 陷阱 | 表现 | 防范 |
| --- | --- | --- |
| 用测试集调参 | 测试技巧远高于验证技巧 | 严格遵守 L4 铁律 |
| 随机打乱划分 | R² 高得离谱（如 0.9+） | 时间块划分 |
| 特征里混入未来信息 | 提前 4 周技巧几乎不衰减 | `check_leakage()` 断言 |
| 树模型外推失败 | 极端年（如 2022）严重低估 | 报告"对极值的低估"作为局限 |
| 过拟合 | 训练 R² 0.9、验证 R² 0.1 | 限制树深、加正则、看泛化间隙 |
| 多重共线性 | 线性模型系数符号与物理预期相反 | 用 Ridge/Lasso，结合相关矩阵诊断 |
| 只看 R² 不看物理 | 挑出物理上无法解释的因子 | 三重证据交叉验证 |
| 类别不平衡下的准确率 | 极端事件 Accuracy 很高但 Recall 很低 | 用 Recall/F1/HSS，不用 Accuracy |
