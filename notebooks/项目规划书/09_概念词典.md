## A. 时间尺度与预测框架

| 概念 | 解释 | 在本项目中的作用 | 常见误区 |
| --- | --- | --- | --- |
| **延伸期预测**（Extended-range forecast） | 指**未来 10—30 天**的预测。它夹在中期天气预报（1—10 天，靠初值）与季节预测（1 个月以上，靠海温等外强迫）之间，可预报性最弱，被称为"预测空档" | 本项目的核心问题：做 1—4 周（7—28 天）的高温预测 | 把"延伸期"当成"长期天气"或"短期气候"；实际上它是独立的时间尺度，可预报性来源与两者都不同 |
| **中期天气预报** | 未来 1—10 天的预报，主要依赖初始条件（初值）与天气系统演变 | 本项目提前 1 周的预测与之有部分重叠，因此持续性基线在第 1 周往往较强 | 以为提前 1 周"很容易"，忽视了它同样需要严格检验 |
| **季节预测** | 未来 1 个月至 1 年以上的预测，主要依赖海温、土壤湿度、冰雪等慢变外强迫 | 提供背景认识（如 ENSO 对夏季环流的影响），但不属于本项目任务范围 | 把延伸期结论外推到季节尺度 |
| **可预报性**（Predictability） | 一个系统在给定的时间尺度上"在原理上能被预测到什么程度"的上限 | 评价模型技巧时必须与可预报性上限对照，避免对过低技巧的过度苛责或对过高技巧的盲目乐观 | 把"模型技巧"与"可预报性"混为一谈：前者是方法能力的度量，后者是物理上限 |
| **可预报性来源** | 延伸期的可预报性主要来自：① 土壤湿度记忆；② MJO/BSISO 等热带季节内振荡；③ 副高与中高纬环流的持续性异常；④ 海温异常的缓慢演变 | 本项目选取预测因子的**全部理由**都来自这几类来源 | 把"某因子与高温相关"当作可预报性来源——相关不等于有超前信息 |
| **前兆信息 / 前兆因子**（Precursor） | 在目标事件发生**之前**已经可以观测到、且与目标事件有物理联系的大气或陆面状态 | 预测因子 X 的本质就是前兆信息 | 用目标时段的同期信息当"前兆"——那是作弊，不是预测 |
| **提前期**（Lead time） | 从发布时刻到目标时段的时间间隔。本项目取 1、2、3、4 周 | 全部结果都按提前期分别报告，得到"技巧随提前期的衰减曲线" | 不区分提前期，把所有结果混在一起报告 |
| **发布时刻 / 起报时刻**（Issue time, `t0`） | 做预测的那一天；这一天及其之前的数据才允许使用 | 防数据泄漏的锚点：所有因子窗口的右端必须 ≤ `t0` | 把"目标日"当成发布时刻 |
| **目标时段 / 预测窗口** | 被预测的那一段时间（如第 8—14 天） | 定义样本表的 Y，并在样本表中以 `target_start`/`target_end` 记录 | 目标时段与发布时刻错位，导致标签与特征不对应 |
| **历史回报检验**（Hindcast） | 用历史上已发生的情形来"重放"一次预测，检验模型在过去的表现 | 本项目 2021—2025 年的独立检验本质上就是一次历史回报 | 把历史回报技巧当作真实实时预报技巧——它未包含实时资料的不确定性 |
| **预测技巧**（Forecast skill） | 预测相对于某个参照（基线）的准确程度，而非绝对准确度 | 所有评价都以技巧评分形式给出 | 只报绝对误差，不与基线比较，无法说明工作价值 |
| **基线 / 基准**（Baseline） | 用来对照的最简单预测方法 | 本项目用气候态与持续性作为两条基线 | 不设基线，或只设一个弱基线来"显摆"提升 |
| **数据泄漏 / 时间信息泄漏**（Data leakage） | 训练过程中无意使用了预测时点之后才可获得的信息，导致评估结果虚高 | 本项目设五条铁律（L1—L5）专门防范 | 认为"只要划分了训练/测试集就没有泄漏"——特征工程、气候态、标准化都可能泄漏 |
| **预测 vs 拟合** | 拟合是"解释已有数据"，预测是"对未见数据给出结果" | 本项目关心的是预测，因此一切评估都在样本外进行 | 用训练集上的 R² 代替预测技巧 |

## B. 数据与观测

| 概念 | 解释 | 在本项目中的作用 | 常见误区 |
| --- | --- | --- | --- |
| **再分析资料**（Reanalysis） | 用数值模式与数据同化技术，把历史上分散的观测融合成时间连续、空间完整的网格化"大气状态重建" | 本项目的数据基础 | 把再分析当作"观测真值"——它本身含有模式误差 |
| **ERA5** | ECMWF 第五代全球大气再分析资料，逐小时、0.25°、1940 年至今 | 全项目唯一核心数据源 | 忘了记录版本与下载参数，导致无法复现 |
| **数据同化**（Data assimilation） | 把观测与模式背景场按误差权重融合、生成最优估计的技术 | 理解"再分析为何无缺测、为何有误差"的关键 | 以为是简单插值 |
| **CDS**（Climate Data Store） | ECMWF 提供的数据下载平台，用 `cdsapi` 通过 API 批量下载 | 成员A 的数据获取渠道 | 忘记申请账号/接受许可条款导致下载失败 |
| **NetCDF / GRIB** | 两种气象常用数据格式，分别用 `xarray`+`netCDF4` / `cfgrib` 读取 | 数据读取与处理 | 直接解析二进制而不统一到 xarray，导致坐标混乱 |
| **网格数据 vs 站点数据** | 网格数据是规则格点上的场；站点数据是离散观测 | 用网格数据做区域平均与因子构造 | 把格点值直接当作站点值使用 |
| **空间分辨率** | 网格的经纬度间隔，ERA5 常用 0.25°（约 25—30 km） | 决定区域内有约几千个格点、决定数据量 | 忽略不同变量分辨率不一致（如 SST 常更粗） |
| **单层 / 气压层数据** | 单层（single levels）指地面与近地面要素；气压层（pressure levels）指各等压面上的要素 | 核心变量多为单层；Z500 与风场来自气压层 | 混淆层次，例如把 850 hPa 高度当作 500 hPa |
| **T2m / 2t**（2 米气温） | 地面以上 2 米处的空气温度，单位 K | 目标变量 Tmax 的来源；也是前期热状态因子 | 忘记 K→°C 换算；忽略"2 米"是诊断高度而非地表温度 |
| **D2m / 2d**（2 米露点温度） | 空气冷却到饱和时的温度，反映水汽含量，单位 K | 前期湿度因子（近地面干湿条件） | 把露点温度当作气温使用；忘记换算为 °C 后 D2m ≤ T2m |
| **MSLP / msl**（平均海平面气压） | 折算到海平面的气压，单位 Pa | 天气尺度环流背景因子 | 忘记 Pa→hPa 换算（差 100 倍，会主导线性模型） |
| **TP / tp**（总降水） | 该时段内的总降水量，ERA5 逐小时数据单位为 m（该小时累积） | 前期降水因子，表征干湿状态 | 忘记 ×1000 换算为 mm；忽略累积量的时间步与跨日边界 |
| **SSRD / ssrd**（地表向下短波辐射） | 到达地表的太阳短波辐射，ERA5 逐小时数据为 J·m⁻²（该小时累积） | 地表能量输入因子 | 忘记除以 3600 换算为 W·m⁻²；与"净辐射"混淆 |
| **SWVL1 / swvl1**（表层土壤体积含水量） | 0—7 cm 土层的体积含水量，单位 m³·m⁻³ | **陆面记忆核心因子**，是延伸期可预报性的重要来源 | 与 SWVL2/3/4（更深层）混淆；忽略其单位是体积比而非百分比 |
| **AVG_SLHTF**（时间平均地表潜热通量） | 地表通过蒸发/蒸腾向大气输送的潜热通量，反映蒸发耗热 | 陆气相互作用因子，检验"蒸散受限 → 感热增强"链条 | 忽略**符号约定**（向上通量常为负），导致 SHAP 方向完全反向；单位随下载口径不同（J·m⁻² 或 W·m⁻²） |
| **Z500**（500 hPa 位势高度） | 500 hPa 等压面的位势高度，单位 gpm | 中层环流因子，用于识别副高与高压脊 | 与几何高度混淆（两者数值接近但定义不同） |
| **850 hPa 风场（U850/V850）** | 850 hPa 等压面上的纬向/经向风分量，单位 m·s⁻¹ | 低层风场、暖平流与水汽输送因子 | 只看风速不看风向；风场是矢量，需分别处理 U、V |
| **SST**（海表温度） | 海洋表面的温度 | 海气相互作用因子，影响副高位置与强度 | 陆地格点无 SST，需先做海洋掩膜 |
| **面积加权**（cos φ 权重） | 区域平均时按格点纬度余弦加权，因为高纬格点代表的实际面积更小 | 保证区域 Tmax 无系统性偏差 | 直接用 `mean()` 平均——高纬格点被过度代表 |
| **区域平均** | 把研究区内所有格点合成为一个代表性序列 | 把二维高温场压缩为一维目标序列 Y | 不说明平均方式（算术平均还是面积加权、是否用最高温） |
| **UTC 与日界** | ERA5 时间标注为 UTC；当地日（如 UTC+8）与 UTC 日界相差 8 小时 | 取"日最高温"时必须按当地日聚合 | 直接按 UTC 日期取日最高，导致日最高温错位数小时 |
| **累积量**（accumulated field） | 表示"某时段内累积"的变量（如 tp、ssrd），而非瞬时值 | 日累计时必须明确累加的起止小时 | 把累积量当瞬时值处理，或跨日累加时少算/多算一小时 |
| **通量符号约定** | 通量方向的正负号定义（向下为正还是向上为正） | 全项目必须统一并写入数据字典 | 符号搞错 → 模型的贡献方向与物理解释全部反向 |
| **缺测与异常值** | 数据中缺失或超出物理合理范围的值 | 质控环节必须检查物理范围（如 SWVL1 ≥ 0） | 直接跳过质控，把填充值当真实值 |
| **质量控制**（QC） | 对数据做时区、单位、范围、连续性等系统性检查 | 本项目列出 10 项质控清单（见 03 文件） | 只在最后出图时"看一眼"，不做系统检查 |

## C. 目标变量与统计量

| 概念 | 解释 | 在本项目中的作用 | 常见误区 |
| --- | --- | --- | --- |
| **Tmax** | 一日之内的最高气温（本项目指 2 米气温的日最高值） | 高温强度的基本度量 | 用日平均温度代替日最高温度 → 与"高温事件"定义脱节 |
| **气候态**（Climatology） | 某地某时的多年平均状态，是"常年情况"的基准 | 计算距平与标准化指数的分母 | 不说明基准期与计算窗口，导致无法复现 |
| **日历日气候态 `Tclim(d)`** | 针对每一个日历日 d（如 7 月 15 日）的气候平均值 | 扣除季节循环的关键量 | 用单日样本计算（样本太少），或不做平滑 |
| **标准差 `σ(d)`** | 该日历日气温的年际变化幅度 | 标准化的尺度因子 | σ 过小导致 H 数值爆炸，需设下限 |
| **距平**（Anomaly） | 实际值减去气候态 | 去掉季节循环后，剩下的才是"异常"部分 | 把距平当作绝对值解释 |
| **标准化 / z-score** | `(x − 均值) / 标准差`，把变量转换为"偏离多少个标准差" | 使不同变量可比、使正则化公平、使 H 具有统一含义 | 用全期数据计算均值方差（泄漏） |
| **标准化高温指数 H** | `H(t) = [Tmax_region(t) − Tclim(d)] / σ(d)`，本项目的第一阶段预测目标 | 全部连续预测与评价的核心目标量 | 把 H 当作温度（它是无量纲的"标准差倍数"） |
| **高温增强幅度 ΔH** | `H(t) − H(t−Δ)`，刻画高温由一般状态向极端状态发展的速度 | 第二阶段扩展目标 | 在第一版模型就引入，增加不必要的复杂度 |
| **去季节循环**（Deseasonalization） | 从序列中扣除季节循环分量 | 使模型必须预测"异常"而非"季节" | 不做这一步 → 模型退化成看日期猜气温，R² 虚高 |
| **分位数**（Quantile / Percentile） | 把数据从小到大排列后，处于某个百分位置的值（如 95% 分位） | 定义极端高温阈值的基础 | 用全期数据算分位（泄漏）；分位阈值在样本少时不稳定 |
| **极端阈值** | 判定"是否极端"的临界值，本项目取 H 的 90% 或 95% 分位 | 把连续预测转换为极端预警 | 阈值定义域不统一（各日历日分别取 vs 全季统一取） |
| **有效样本量** | 考虑自相关后，样本的"独立信息量"，通常远小于名义样本数 | 显著性检验与置信区间的正确计算依据 | 直接用样本天数 n 做检验 → 显著性被人为高估 |
| **自相关**（Autocorrelation） | 时间序列与自身滞后版本的相关性 | 高温与土壤湿度都有强自相关，是持续性基线有效的原因，也是统计检验的障碍 | 忽略自相关，把连续样本当作独立样本 |
| **趋势 / 年代际变化** | 序列在长时间尺度上的单调变化或阶段性变化 | 影响因子与目标的关系稳定性（需做分年代检验） | 把长期变暖趋势误当作"可预测信号" |

## D. 机器学习模型

| 概念 | 解释 | 在本项目中的作用 | 常见误区 |
| --- | --- | --- | --- |
| **线性回归 / OLS** | 用最小二乘法拟合 `y = β₀ + Σβⱼxⱼ` | 第 L2 层基线；系数可直接解释方向与强度 | 不做标准化就比较系数大小（量级不同不可比） |
| **多重共线性** | 自变量之间高度相关，导致回归系数不稳定、符号反常 | 气象因子普遍存在（TP 与 SWVL1 等） | 把系数符号异常解释为物理机制 |
| **正则化**（Regularization） | 在损失函数中加入对系数大小的惩罚，抑制过拟合 | 稳定线性模型、提升泛化 | 惩罚强度（α）不用验证集选 |
| **Ridge（L2 正则）** | 惩罚系数平方和，把系数整体缩小但不置零 | 处理共线性的首选线性模型 | 以为 Ridge 能做变量筛选（它不能把系数变 0） |
| **Lasso（L1 正则）** | 惩罚系数绝对值之和，可把无用系数压缩为 0 | 辅助变量筛选 | 共线性下 Lasso 会随机保留其中一个变量，结果不稳定 |
| **决策树**（Decision tree） | 递归地按特征阈值划分样本、在叶节点给出预测的模型 | 随机森林与提升法的基本单元 | 单棵树极易过拟合 |
| **Bagging** | Bootstrap 重采样 + 聚合：对训练集有放回抽样训练多个模型再平均 | 随机森林的核心思想 | 与 Boosting 混淆 |
| **随机森林**（Random Forest） | 多棵决策树的 Bagging 集成，每次分裂还随机抽取部分特征 | 第 L3 层模型；刻画非线性、稳健 | 用它外推极端值（树模型无法外推） |
| **梯度提升**（Gradient Boosting） | 串行加树，每棵新树拟合当前模型的损失负梯度（近似残差） | XGBoost/LightGBM/CatBoost 的共同框架 | 以为树越多越好——会过拟合 |
| **XGBoost** | 高效梯度提升实现，带正则项、行列采样、缺失值处理与并行优化 | 第 L4 层核心模型 | 默认超参数直接用于小样本气象数据 → 严重过拟合 |
| **LightGBM / CatBoost** | 另两个主流梯度提升实现，速度或类别特征处理上各有优势 | 作为**鲁棒性检验**（换算法结论是否一致） | 第一阶段同时调三个模型，分散精力 |
| **残差**（Residual） | 真实值与当前预测值之差 | 提升法的拟合目标 | 把残差与误差、偏差混为一谈 |
| **学习率**（Learning rate） | 每棵树对最终预测的贡献缩放系数 | 提升法最重要的超参数之一：小学习率 + 多树通常更稳 | 学习率大 + 树多 → 过拟合 |
| **树深**（max_depth） | 单棵树的最大层数，控制模型复杂度 | 本项目信号弱、样本少，树深宜取 2—4 | 用默认的 6 或更深 |
| **超参数**（Hyperparameter） | 训练前需人为设定、不能由数据直接学出的参数（树数、深度、学习率等） | 在验证集上调优，绝不用测试集 | 把模型参数（权重）也叫超参数 |
| **过拟合**（Overfitting） | 模型记住训练集噪声，训练表现好但验证/测试表现差 | 需通过限制复杂度、正则化、早停防范 | 只看训练集指标就宣布成功 |
| **欠拟合**（Underfitting） | 模型太简单，训练与验证表现都差 | 说明需要更复杂的模型或更多有效因子 | 与"信号本身弱"混淆 |
| **泛化**（Generalization） | 模型在未见数据上的表现能力 | 本项目的最终目标 | 用交叉验证的乐观估计代替真正的样本外检验 |
| **外推**（Extrapolation） | 对训练数据范围之外的取值做预测 | 树模型不能外推，因此对破纪录高温会低估——这是必须披露的局限 | 期望 XGBoost 能预测出历史最强高温 |
| **分位数回归** | 直接优化条件分位数（如 90% 分位）而非均值 | 二阶段极端识别的路线 2 方案 | 仍用均方误差损失却期望它抓极值 |
| **样本加权** | 训练时给不同样本不同权重 | 提高极端样本权重，增强极端事件识别 | 权重设得过大导致模型只关注极值、整体技巧崩塌 |
| **集成学习**（Ensemble） | 组合多个模型以提升稳健性 | 随机森林与提升法都属于集成方法 | 以为"集成一定更好"——弱模型集成也可能更差 |
| **LSTM / Transformer** | 处理序列的深度神经网络结构 | 本项目**第一阶段不做**；待基础流程跑通后作为拓展 | 样本量小时直接上深度模型 → 过拟合且不可解释 |
| **气候态基线** | 用气候平均作为预测，本项目因 H 已去气候态，故 `Ŷ = 0` | 技巧评分的最重要分母 | 忘记它的存在，导致技巧无法解读 |
| **持续性基线** | 用发布时刻前观测到的 H（或提前 k 周前的 H）作为预测 | 检验模型是否超越"高温自己会持续"这一朴素规律 | 只与气候态比较，高估了机器学习价值 |

## E. 验证与实验设计

| 概念 | 解释 | 在本项目中的作用 | 常见误区 |
| --- | --- | --- | --- |
| **训练集 / 验证集 / 测试集** | 分别用于拟合参数、调超参数、最终评估的数据子集 | 本项目按年份划分为 1981—2015 / 2016—2020 / 2021—2025 | 三个集合职责混用 |
| **时间块划分** | 按连续时间段（年份）划分数据集 | 避免时间信息泄漏的标准做法 | 用随机划分（K 折 shuffle）——气象时序中的致命错误 |
| **滚动验证**（Rolling / Walk-forward） | 训练窗口逐步前移，得到多次"训练—验证"结果 | 给出技巧的年际分布与稳定性，弥补单一验证集样本不足 | 认为各折结果完全独立 |
| **交叉验证**（CV） | 把数据分成多折轮流做验证 | 时序问题中必须用 `TimeSeriesSplit` 型 CV | 用随机 K 折 |
| **模型冻结**（Freeze） | 把特征、超参数、种子等全部写死并记录哈希，之后不再改动 | 保证测试集独立性的操作纪律 | 冻结后又"微调一下" |
| **消融实验**（Ablation） | 系统性地增删某部分输入/结构，观察性能变化 | 本项目用 A—E 五组变量分组做消融，量化各类变量的增量技巧 | 只做单变量重要性，不看分组增量 |
| **对照组** | 除被检验因素外其余条件完全一致的实验组 | 消融实验只改输入变量集合 | 同时改多个条件，无法归因 |
| **随机种子**（Seed） | 控制随机过程的初始值，保证结果可复现 | 数据划分、模型初始化、bootstrap 都要固定 | 不记录种子 → 结果无法复现 |
| **可复现性** | 他人用相同数据与代码能得到相同结果 | 用 `uv` 锁环境、配置驱动、实验日志留痕 | 代码里硬编码路径与参数 |
| **调参**（Tuning） | 搜索最优超参数的过程 | 只在训练+验证上做 | 用测试集选最优 |
| **早停**（Early stopping） | 验证集指标不再改善时停止训练 | 提升法防止过拟合的常用手段 | 早停用的验证集又用于最终评估，造成轻微乐观 |

## F. 评价指标

| 概念 | 解释 | 在本项目中的作用 | 常见误区 |
| --- | --- | --- | --- |
| **MAE**（平均绝对误差） | 误差绝对值的平均 | 连续预测的基础指标，稳健 | 单独用 MAE 会掩盖少量大误差 |
| **RMSE**（均方根误差） | 误差平方平均后再开方 | 主选调参指标，对大误差敏感 | 与 MAE 混用时不说明差异含义 |
| **皮尔逊相关系数 R** | 两序列线性同步变化的度量，取值 [−1,1] | 衡量"预测是否跟着真值变化" | 只看 R 不看偏差与振幅 |
| **决定系数 R²** | `1 − SSE/SST`，解释的方差比例 | 综合指标 | 忘记 R² 可以为负；把它等同于 R 的平方 |
| **偏差 Bias** | 预测减真实的平均 | 检测系统性高估/低估 | 忽略偏差，误以为"平均误差为 0 就没问题" |
| **技巧评分**（Skill score） | `1 − MSE_model/MSE_ref`，相对基线的改进 | 回答"机器学习比简单方法好多少" | 不指明参照基线 |
| **ACC**（异常相关系数） | 去掉气候态后的相关系数 | 气象领域通用技巧度量；本项目 H 上的 R 即近似 ACC | 在含季节循环的原始温度上算 ACC |
| **标准差比** | `σ(预测) / σ(真实)` | 检测预测是否过度平滑（振幅压缩） | 忽略它，导致"R 不错但强度总是偏弱" |
| **混淆矩阵** | TP/FP/FN/TN 的四格计数表 | 分类指标的计算基础 | 只看总数不看结构 |
| **Precision**（查准率） | `TP/(TP+FP)`，报出的极端有多少是真的 | 预警可信度 | 与 Recall 混淆 |
| **Recall**（查全率） | `TP/(TP+FN)`，真实极端抓到了多少 | **预警最关键指标**（漏报代价高） | 为提高 Precision 牺牲 Recall |
| **F1** | Precision 与 Recall 的调和平均 | 不平衡数据下的综合指标 | 把 F1 当作唯一标准，忽略业务代价 |
| **ROC-AUC** | ROC 曲线下面积，衡量排序能力 | 阈值无关的判别能力 | 类别极不平衡时过于乐观 |
| **PR-AUC** | Precision-Recall 曲线下面积 | 极不平衡数据下更敏感，本项目首选 | 与 ROC-AUC 混用 |
| **HSS**（Heidke Skill Score） | 相对随机预测的分类技巧 | 气象领域标准评分 | 不说明 HSS>0 才算有技巧 |
| **TSS**（True Skill Statistic） | `Recall + Specificity − 1` | 不受类别比例影响 | 与 HSS 数值混淆 |
| **BSS**（Brier Skill Score） | 概率预报相对气候态概率的改进 | 概率型预警的技巧评分 | 用于硬判定结果 |
| **类别不平衡** | 正类样本远少于负类（如极端只占 5%） | 极端事件评价的核心难点 | 用 Accuracy 评价 |
| **Accuracy 陷阱** | 不平衡数据下全报"非极端"也有 90%+ 准确率 | 因此本项目基本不使用 Accuracy | 在论文中把 Accuracy 作为主要指标 |
| **Bootstrap** | 有放回重采样估计统计量分布的方法 | 计算指标的置信区间 | 对时间序列用简单 bootstrap（需分块） |
| **分块 bootstrap** | 按连续时间块重采样的 bootstrap | 处理自相关，得到可信的置信区间 | 忽略块长选择 |
| **置信区间** | 参数估计的不确定范围 | 报告 `R = 0.42 [0.28, 0.55]` 而非单点值 | 只报点估计 |
| **显著性检验 / p 值** | 判断结果是否可能由随机造成 | 机制诊断的必要环节 | 在有自相关的时间序列上直接套用经典公式 |
| **Diebold–Mariano 检验** | 检验两个模型预测误差是否有显著差异 | 回答"XGBoost 是否真的显著优于 RF" | 只比较数值大小就下结论 |

## G. 可解释性方法

| 概念 | 解释 | 在本项目中的作用 | 常见误区 |
| --- | --- | --- | --- |
| **可解释人工智能（XAI）** | 让模型决策过程可被人理解的方法集合 | 本项目"模型解释"环节的总称 | 把解释结果当作因果证明 |
| **SHAP** | 基于博弈论 Shapley 值的模型解释方法，把预测分解为各特征的贡献 | 识别关键因子、分析贡献方向、分提前期对比 | 认为 SHAP 排名就是物理重要性排序 |
| **Shapley 值** | 合作博弈中按边际贡献公平分配收益的解 | SHAP 的数学基础 | 以为它衡量因果效应 |
| **TreeSHAP** | 针对树模型的精确高效 SHAP 算法 | 本项目计算 SHAP 的主力算法 | 对非树模型也期待同等效率 |
| **Summary / 蜂巢图** | 每个变量一行的 SHAP 分布图，颜色表示特征值高低 | 同时看重要性排序与贡献方向 | 只看颜色不看分布重叠 |
| **Dependence Plot** | 横轴为特征值、纵轴为 SHAP 值 | 观察关系形状与阈值效应 | 忽略图中颜色代表的交互变量 |
| **Waterfall / Force Plot** | 单个样本的贡献分解 | 解释某一年极端高温为何被预测出来 | 用单样本结论推广到全局 |
| **Permutation Importance** | 打乱某特征后看性能下降多少 | 与模型结构无关的预测价值度量 | 在训练集上做；对相关特征不整组打乱 |
| **特征重要性** | 各类方法给出的"变量有多重要"的度量总称 | 用于初筛与交叉印证 | 只看一种方法就下结论 |
| **相关特征分摊贡献** | 相关变量共同解释同一份信号，导致各自的重要性被稀释 | 因此必须用分组消融补充 | 因 SHAP 排名低就断言"该物理因子不重要" |

## H. 物理机制与气候概念

| 概念 | 解释 | 在本项目中的作用 | 常见误区 |
| --- | --- | --- | --- |
| **陆气相互作用**（Land–atmosphere interaction） | 陆面（土壤湿度、植被）与大气之间通过能量、水分交换相互影响 | 延伸期可预报性的核心来源之一 | 只把它当作"背景知识"，不落到具体因子 |
| **土壤湿度** | 土壤中的含水量，决定蒸发能力 | SWVL1 是核心预测因子 | 忽略不同深度的土壤湿度代表不同记忆长度 |
| **土壤湿度记忆** | 土壤湿度异常可以维持数周，从而把前期异常"传递"给后期天气 | 解释为什么提前 2—4 周仍可能可预测 | 认为土壤湿度只影响当天 |
| **土壤湿度—气温反馈** | 土壤偏干 → 蒸发减少 → 地表升温 → 进一步变干的正反馈 | 高温持续与增强的机制核心 | 忽略"感热/潜热分配"这一中间环节 |
| **蒸散**（Evapotranspiration） | 土壤蒸发与植物蒸腾的总和，是地表主要的潜热耗散过程 | 连接土壤湿度与近地面温度的桥梁 | 与降水混淆 |
| **潜热通量**（Latent heat flux） | 水相变携带的热量通量，蒸发时从地表带走热量（冷却地表） | AVG_SLHTF，检验"蒸散受限"链条 | 忽略符号约定导致方向判断反向 |
| **感热通量**（Sensible heat flux） | 地表与大气之间因温差产生的热量交换 | 潜热减少时感热增加，直接加热近地面空气 | 忽略潜热—感热的能量分配关系 |
| **边界层**（Boundary layer） | 受地表直接影响的大气底层（约 1—2 km） | 陆面异常通过边界层影响近地面气温 | 与对流层等概念混淆 |
| **下沉增温**（Subsidence warming） | 空气下沉时被压缩而绝热增温 | 副高控制下高温形成的关键机制 | 与平流增温混淆 |
| **绝热增温** | 气块在无热量交换的情况下因压缩而升温 | 理解下沉增温的物理基础 | 认为是外部加热 |
| **西太副高**（WPSH, Western North Pacific Subtropical High） | 西北太平洋上的副热带高压系统，其西伸北抬常控制长江中下游 | 高温环流背景的核心系统 | 只看强度不看位置（西伸脊点、北界同样关键） |
| **位势高度**（Geopotential height） | 等压面相对于海平面的"重力位势高度" | Z500 的物理含义 | 与几何高度完全等同看待 |
| **高度异常场** | 某时刻位势高度减去气候态得到的场 | 识别副高与高压脊异常的诊断工具 | 忘记扣除气候态 |
| **反气旋** | 北半球顺时针旋转的环流，中心为高压，伴随下沉气流 | 850 hPa 风场异常诊断的判据 | 只看风向不看是否闭合 |
| **暖平流** | 风把暖空气输送到某地 | 850 hPa 风场影响高温的机制之一 | 忽略水汽输送的相反作用 |
| **遥相关 / 波列** | 相隔遥远区域之间环流异常的关联形态 | 解释海温如何影响长江中下游 | 在样本有限时过度解读波列 |
| **MJO / BSISO** | 热带大气季节内振荡（10—90 天，MJO 沿赤道东传，BSISO 为北半球夏季型） | 延伸期可预报性的重要来源 | 把它等同于本项目的时间尺度而忽略中高纬信号 |
| **季节内振荡** | 时间尺度在 10—90 天的准周期振荡 | 延伸期预测的物理背景 | 与天气尺度（几天）混淆 |
| **合成分析**（Composite analysis） | 按事件分组求平均场并作差，得到典型异常形态 | 机制诊断的主力方法 | 不说明事件定义与样本数 |
| **超前 / 滞后合成** | 以事件日为基准，合成事件前后不同时次的异常场 | 直接展示"高温发生前几周哪个因子先异常" | 只做同期合成，无法体现"前兆" |
| **异常场** | 实际场减气候态 | 诊断的核心对象 | 用原始场做合成，季节循环掩盖信号 |
| **显著性检验**（气象） | 判断异常是否超出随机波动的统计手段 | 机制结论的必备支撑 | 忽略自相关与多重检验问题 |
| **年代际变化** | 时间尺度约 10 年以上的气候背景变化 | 检验关系稳定性的分组依据 | 忽略它，把不稳定的关系当作普适规律 |
| **海气相互作用** | 海洋与大气之间的热量、动量交换 | SST 影响高温环流的桥梁 | 把 SST 与高温的关系简单当作线性 |
| **高温过程 / 热浪定义** | 连续多日超过阈值的事件定义方式 | 极端事件评价的事件化选项 | 与单日阈值判据混用而不说明 |

## J. 一页速查（答辩高频提问）

| 提问 | 一句话回答 |
| --- | --- |
| 什么是延伸期？ | 未来 10—30 天，介于中期天气与季节预测之间的预测空档。 |
| 为什么用 H 而不是直接用温度？ | 扣掉季节循环，模型才能预测"异常"而不是"季节"。 |
