## 一、预测目标 Y 的构建链路

```
逐小时 T2m（网格）
   ↓ ① 按当地日界取日最高
逐日 Tmax（网格）
   ↓ ② 区域面积加权平均
区域 Tmax 时间序列 Tmax_region(t)
   ↓ ③ 计算日历日气候态 Tclim(d) 与标准差 σ(d)
   ↓ ④ 标准化
标准化高温指数 H(t)
```

### 1.1 逐日最高气温 Tmax

对每个网格、每个当地日，取该日内所有逐小时 2 米气温的最大值：

```
Tmax_i(t) = max { T2m_i(τ) : τ ∈ 当地日 t }
```

其中 `i` 为网格索引。**注意时区**：ERA5 时间标注为 UTC，
若研究区取 UTC+8，则当地日 t 覆盖 `[t-1 日 16:00 UTC, t 日 15:00 UTC]`
（详见 [`03_数据与变量方案.md`](03_数据与变量方案.md) 第五节第 1 条）。

### 1.2 区域平均

```
Tmax_region(t) = Σ_i w_i · Tmax_i(t) / Σ_i w_i ,   w_i = cos(φ_i)
```

- `w_i = cos(φ_i)` 为**面积权重**，`φ_i` 为格点纬度；
- 不做面积加权会让高纬格点被过度代表，区域平均产生系统性偏差；
- 也可以用区域内的最高温（而非平均）来定义"区域极端"，但需在方案中明确并固定。

### 1.3 气候态与标准差

```
Tclim(d) = 日历日 d 的气候态（多年平均）
σ(d)     = 日历日 d 的标准差
```

**计算细节（必须在方案中写清楚）：**

| 项目 | 建议做法 | 理由 |
| --- | --- | --- |
| 窗口 | 以日历日为中心取 ±5 天（共 11 天）滑动窗口，跨年合并样本 | 单日样本太少，11 天窗口可显著降低采样噪声 |
| 基准期 | **只用训练期年份（1981—2015）计算**，或使用固定的 WMO 基准期（如 1991—2020） | 见下方"泄漏警告" |
| 平滑 | 可选：对 Tclim(d) 与 σ(d) 做低阶谐波拟合（如保留前 2—4 个谐波） | 消除窗口滑动带来的锯齿，保留季节循环 |
| σ 的下限 | 设一个下限（如不小于全季 σ 的某个比例），防止个别日历日 σ 过小导致 H 爆炸 | 数值稳健性 |

> ⚠️ **泄漏警告**：如果气候态用**全部 45 年**计算，那么测试年（2021—2025）
> 的信息就通过 `Tclim(d)` 和 `σ(d)` 间接进入了目标变量与特征标准化过程，
> 属于**轻度数据泄漏**。严谨做法是：**气候态与所有标准化参数只用训练期估计**，
> 在验证/测试时"冻结"使用。若为了与文献可比而使用全期气候态，
> 必须在报告中明确说明并做一次敏感性检验。

### 1.4 标准化高温指数 H

```
H(t) = [ Tmax_region(t) − Tclim(d) ] / σ(d)
```

**H 的统计含义**：H 是**标准化的距平**（z-score）——它回答的是
"这一天比该日历日的常年平均热了多少个标准差"。

| H 的取值 | 含义 |
| --- | --- |
| H ≈ 0 | 与常年同期相当 |
| H = +1 | 比常年偏热 1 个标准差 |
| H = +2 | 显著偏热，接近或达到极端阈值（若阈值取 95% 分位，对应约 +1.65σ） |
| H < 0 | 偏凉 |

**为什么要标准化？** 5—8 月本身气温从"初夏"升到"盛夏"再回落，
若不扣除季节循环，模型会退化成一个"看日期猜气温"的季节预报器，
既没有延伸期预测意义，也会得到虚高的 R²。

### 1.5 高温增强幅度 ΔH（第二阶段扩展目标）

```
ΔH(t) = H(t) − H(t − Δ)     （Δ 可取 1 天或 1 周）
```

ΔH 描述"高温由一般状态向极端状态发展的增强速度"。
原方案建议：**第一版模型优先以 H 为连续预测目标**，
待完整流程跑通后再增加 ΔH。

## 二、预测目标的三种可选定义

| 定义 | 表达式 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- | --- |
| **T1：日 H** | Y = H(t) | 样本量最大（约 5500 天） | 日尺度噪声大；相邻样本高度相关 | 可作为基础版本 |
| **T2：周平均 H**（推荐主目标） | Y = mean{ H(t') : t' ∈ 目标周 } | 与"提前 k 周预测"的语义一致；噪声更小 | 样本量降为约 1/7（约 780 个） | **主目标** |
| T3：ΔH | Y = H(t) − H(t−7) | 直接刻画增强过程 | 定义复杂，物理解释更难 | 第二版扩展 |

> **务必在 P0 阶段二选一并冻结**。T1 与 T2 的样本表结构不同，
> 中途切换会导致全部结果作废。

## 三、预测时刻与目标时段：提前期的严格定义

这是延伸期预测的**核心纪律**。

### 3.1 符号约定

| 符号 | 含义 |
| --- | --- |
| `t0` | **发布时刻**（forecast issue time）：做预测的那一天，只能用这一天及之前的信息 |
| `k` | 提前期（lead time），单位：周，k = 1, 2, 3, 4 |
| 目标窗口 | 第 k 周对应的目标时段，例如 `[t0 + 7(k−1) + 1, t0 + 7k]` |

### 3.2 对应关系

```
X(t0−7)  → H(t0)     # 提前 1 周
X(t0−14) → H(t0)     # 提前 2 周
X(t0−21) → H(t0)     # 提前 3 周
X(t0−28) → H(t0)     # 提前 4 周
```

更精确地说（以周平均目标为例）：

| 提前期 | 发布时刻 | 目标窗口 | 允许使用的最近数据 |
| --- | --- | --- | --- |
| 第 1 周 | 第 0 天 | 第 1—7 天 | 第 0 天（含）及以前 |
| 第 2 周 | 第 0 天 | 第 8—14 天 | 第 0 天（含）及以前 |
| 第 3 周 | 第 0 天 | 第 15—21 天 | 第 0 天（含）及以前 |
| 第 4 周 | 第 0 天 | 第 22—28 天 | 第 0 天（含）及以前 |

### 3.3 因子不取"瞬时值"，而取"前期状态"

原方案的关键提示：**预测因子不一定只取提前某一天的瞬时值**，
更建议构建**前期一段时间的平均、累计或异常状态**：

- 前期 7 天平均土壤湿度（比单日瞬时值稳健得多）；
- 前期 7 天累计降水；
- 前期 14 天平均 Z500 异常；
- 前期 7 天平均 T2m。

**理由**：
1. 降低天气尺度噪声——单日瞬时值受一次天气过程影响太大；
2. 增强物理意义——土壤湿度记忆、环流持续性本身就是"一段时间"的累积效应；
3. 减少样本偶然性，提升模型稳定性。

**但必须遵守窗口右端约束**：任何聚合窗口的结束时刻 ≤ `t0`。

## 四、机器学习样本表设计

每一行 = 一个"预测样本"；`Y` 为目标时段的高温指数，`X` 为对应的前兆特征。
**提前 1、2、3、4 周分别构建独立数据集**（四张表）。

### 4.1 样本表结构（示意）

| date（目标日/周） | issue_date | lead_week | Y = H | T2m_pre7 | D2m_pre7 | MSLP_pre7 | TP_pre7sum | SSRD_pre7 | SWVL1_pre7 | SLHTF_pre7 | … |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1981-05-15 | 1981-05-08 | 1 | 0.82 | 25.1 | 15.2 | 1008 | 3.2 | 18.4 | 0.26 | … | … |
| 1981-05-16 | 1981-05-09 | 1 | 1.03 | 25.6 | 16.1 | 1007 | 1.1 | 20.3 | 0.24 | … | … |

> 表中 `D2m` 一列若用开尔文表示应为 288—290 K 量级；
> 此处示意值仅为占位，实际以数据字典中的单位为准。

### 4.2 必填元数据列

| 列名 | 用途 |
| --- | --- |
| `issue_date` | **发布时刻**，防泄漏校验的关键列 |
| `target_start` / `target_end` | 目标窗口起止，便于追溯 |
| `lead_week` | 提前期标签（1/2/3/4） |
| `year` | 用于按年份划分数据集与统计 |
| `Y_raw` | 区域 Tmax 原始值（用于反向换算与物理解释） |
| `H`（=Y） | 标准化目标 |

**没有 `issue_date` 与 `target_start/end` 的样本表一律视为不合格**——
它们是把"防泄漏"从口号变成可执行校验的前提。

### 4.3 样本量估算与自相关

- 5—8 月约 123 天/年 × 45 年 ≈ **5535 天**；
- 若目标为周平均，样本量降至约 **780 个**；
- 分提前期后每张表样本量不变（同一批目标，不同发布时刻）。

⚠️ **自相关提醒**：相邻样本的 Y 高度相关，导致**有效样本量远小于名义样本量**。
后果：
1. 相关系数与技巧评分的**置信区间比名义值宽**；
2. 显著性检验必须用**分块 bootstrap** 或考虑自相关的有效自由度，
   不能直接用 `n` 代入常规公式。

## 五、数据泄漏防线（五条铁律）

> **时间信息泄漏**（temporal leakage）指模型在训练时"偷看"了未来信息，
> 导致验证/测试技巧虚高，是气象机器学习最常见、最致命的错误。

| # | 铁律 | 具体做法 | 违反后果 |
| --- | --- | --- | --- |
| **L1** | **禁止随机打乱划分** | 绝不把 1981—2025 年的相邻日期随机拆成训练/测试集；必须按**年份或时间块**划分 | 同一段天气过程同时出现在训练与测试集，技巧虚高 |
| **L2** | **因子窗口右端 ≤ 发布时刻** | 所有聚合窗口、滞后算子的结束时间不得晚于 `issue_date`；写自动化校验脚本 | 直接使用了目标时段信息，预测变成"事后解释" |
| **L3** | **标准化/气候态只用训练期拟合** | `Tclim(d)`、`σ(d)`、各因子的均值方差、缺失值填充值，全部只在训练期估计，再"冻结"应用到验证/测试 | 测试期统计特征泄漏进训练过程 |
| **L4** | **调参与选因子只看验证集** | 超参数搜索、变量筛选、消融实验，全部在训练 + 验证上完成 | 用测试集调参 = 测试集失去独立性 |
| **L5** | **测试集只用一次** | 模型冻结后一次性预测 2021—2025；结果不好也**不得**回头改因子或超参数 | 相当于把测试集变成第二个验证集，报出的技巧不可信 |

**落地手段**：写一个 `check_leakage()` 校验函数，对样本表逐行断言：

```python
assert (df["issue_date"] < df["target_start"]).all()
assert (df["feature_window_end"] <= df["issue_date"]).all()
assert set(train_years).isdisjoint(test_years)
```

并在 CI 或每次数据更新后自动运行。
